# 双班架构与实测战报（V1.4-测试实例 分支）

> 本文档沉淀 2026-10-30 ~ 10-31 实测区（真实 NapCat + 真实群友流量）的架构定稿、
> 回源补丁与运维经验。对应接力笔记「双班架构 v6」。

## 一、双班制（昼夜双脑）

| 班次 | 时段（默认） | 谁值班 | 行为 |
|---|---|---|---|
| 日班 | 09:00~23:00 | 独立大脑 `persona_mcp.py --brain` | 秒级轮询人格回复、随机 20~45 分钟主动搭话、回复成功后实时沉淀 |
| 夜班 | 23:00~次日 09:00 | 事件驱动看门 `server/inbox_watch.py` + ZCode 会话 | 每秒查收件箱，有消息即退出唤醒会话处理 |

- 班次小时可配置：`brain.duty_start_hour` / `brain.duty_end_hour`（支持跨午夜班，如 22~06），
  看门脚本与大脑共用同一份配置，换班精确到秒、互斥铁律不破。
- 窗口外双方都长睡歇班：零查询、零空转、零模型成本。
- 大脑开工时跳过开工时刻前创建的消息（夜班交接区的消息归夜班），防双脑重复回复。

## 三、守护生态（本次正式化进仓库）

| 脚本 | 作用 |
|---|---|
| `server/inbox_watch.py` | 双班制看门（日班长睡/夜班秒查），ZCode 后台任务与 24h 常驻两用；`INBOX_WATCH_MAX_SECONDS` 控制重挂超时 |
| `scripts/brain_supervisor.py` | 大脑自愈守护：进程退出 10 秒自动重启，尊重 `<DATA_DIR>/brain.off` 旗标 |

| `scripts/napcat_launch.py` | NapCat 启动器：DPAPI 解密托管凭据注入 `ACCOUNT`/`NAPCAT_QUICK_PASSWORD`，快速登录票据失效时密码兜底免扫码（不回显明文） |

## 四、运维 SOP（实测沉淀）

- 掉线判定口诀：**OneBot 端口不通而 WebUI 活 = 掉线**（`qq_relogin` 可自动恢复）；
  **两个都挂 = 进程死**（重拉 NapCat：`start_napcat` 或 `scripts/napcat_launch.py`）。
- Git Bash 环境下拉起后台进程用 `powershell Start-Process`，禁用 `start` 命令。
- 限频模型（免费档 3RPM）：突发 429 已内置指数退避（封顶 `brain.backoff_max_seconds`），
  退避期消息保留待补，恢复后自动续答。
- 密码托管经 DPAPI 加密落盘，仅本机本用户可解密，任何接口不回显明文。

## 五、实测战果与教训

- 真实流量验证通过：人格回复、实时沉淀（记忆/关系画像/记忆图联动）、掉线自动恢复
  （hash 认证 + 快速登录）、托管密码兜底链路。
- 画像/好感体系在真实群聊中自然生长；曾误判的贡献者经人工复核平反（具体身份信息不记录于公开仓库）。
- 教训：值班唤醒后先查"待兑订单"类未完成约定（防早安问候漏发）。
- 待办：托管密码的密码登录兜底首验（需票据真正失效时实测）。
